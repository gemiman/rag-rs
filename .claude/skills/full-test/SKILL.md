# 完整测试 RAG 知识库问答系统

针对「RAG 知识库问答系统」这个项目，运行**后端 Rust 单元测试**并给出**明细报告**，按下面步骤：

## 第一步：跑测试，拿逐条结果

1. 在 `backend/` 目录下运行 `cargo test`（会自动逐条列出每个测试用例的名字和 ✅/❌ 结果）。
   - 一定要在 `backend/` 目录跑，**不要**在项目根目录跑（根目录没有 Cargo.toml，会报错）。
   - 这些是纯函数测试，不碰 Redis / SQLite / 百炼 API，所以**不用先启动 Docker、不用填 API Key** 也能跑。
2. 把输出里每一行 `test 模块::测试名 ... ok / FAILED` 记下来，作为明细依据。

## 第二步：生成明细报告（汇总 + 明细）

报告必须包含**汇总**和**明细**两部分。明细按「模块」分组，每组列出：测试文件、测的功能、用例数，以及**每一个用例的名字和 ✅/❌ 状态**。格式如下：

```
## 测试汇总
- 测试文件：5 个（全部通过 ✅）
- 测试用例：N 个（全部通过 ✅）
- 失败：0 个
- 耗时：约 X 秒

## 测试明细（按模块）

### 一、认证（auth）
- 文件：backend/src/auth.rs ｜功能：密码散列/校验、JWT 签发/解析｜共 X 个
  - ✅ test_hash_and_verify_password
  - …（每个用例一行，标 ✅/❌）

### 二、向量存储（vectorstore）
- 文件：backend/src/vectorstore.rs ｜功能：f32↔字节、FT.SEARCH 结果解析｜共 X 个
  - …

### 三、文档切块与解析（ingestion）
- 文件：backend/src/ingestion.rs ｜功能：文本切块、txt/md/csv 解析｜共 X 个
  - …

### 四、缓存哈希（cache）
- 文件：backend/src/cache.rs ｜功能：FNV-1a 哈希、向量字节转换｜共 X 个
  - …

### 五、时间工具（models）
- 文件：backend/src/models.rs ｜功能：now() 时间格式｜共 X 个
  - …
```

归类规则（固定，别搞错）：
- `auth.rs` → 认证
- `vectorstore.rs` → 向量存储
- `ingestion.rs` → 文档切块与解析
- `cache.rs` → 缓存哈希
- `models.rs` → 时间工具

## 第三步：下结论

- 全部通过 → 告诉用户「所有测试通过，后端核心逻辑正常」。
- 有失败 → 判断是「代码有 bug」还是「测试写错了」，用大白话说明原因并给修复建议；修好后重跑直到通过。

## 铁律：如实汇报，绝不编造

- **必须真的运行测试命令，用命令的真实输出**生成报告，禁止凭记忆编数字。
- 如果命令报错，就把真实报错告诉用户，不要假装「全部通过」。

## 这套测试覆盖了什么（大白话）

- **认证**（`auth.rs`）：密码能不能正确散列/校验、JWT 令牌能不能正确签发/解析、错误密码/错误密钥会不会被拒绝。
- **向量存储**（`vectorstore.rs`）：f32 向量和字节怎么互转、Redis 检索结果怎么解析成结构化数据。
- **文档切块与解析**（`ingestion.rs`）：长文本怎么切成不超过限制的小块、txt/md/csv 等文件怎么解析、不支持格式怎么报错。
- **缓存哈希**（`cache.rs`）：FNV-1a 哈希是不是确定且正确、向量字节转换对不对。
- **时间工具**（`models.rs`）：`now()` 返回的是不是合法时间格式。

## 写测试时要注意的坑

- **只在 `backend/` 目录跑**：`cargo test` 必须在 `backend/` 下执行。
- **纯函数测试不需要外部服务**：这些测试都不碰 Redis / SQLite / 百炼 API，所以不用先启动 Docker 或填 API Key。
- **私有函数用内联测试模块**：`vectorstore.rs` 的 `parse_search_result`、`cache.rs` 的 `bytes_to_f32` 等是私有的，测试写在各自文件末尾的 `#[cfg(test)] mod tests` 里（配合 `use super::*`）才能访问到。
